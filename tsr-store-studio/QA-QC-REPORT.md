## 3. Defect Log

### DEF-01 — คีย์ลัดถูกเรียกซ้ำ 2 ครั้ง (Severity: **High**)
- **อาการ**: กด `Ctrl+Z` / `Ctrl+Y` / `Delete` / `R` / `Esc` แล้วคำสั่งทำงานสองรอบ (undo ถอย 2 ขั้น, Delete ยิงซ้ำ, Esc ปิด modal พร้อมเปลี่ยนโหมด)
- **สาเหตุ**: มี `keydown` listener สองตัว — ตัวใหม่ (ระบบ drafting ที่เพิ่มใน v6) และตัวเดิมใน `wire()` ต่างเรียก `undo()/redo()/deleteSelected()`
- **หลักฐาน**: `document.addEventListener('keydown', …)` ที่บรรทัด ~3519 และ `window.addEventListener('keydown', …)` ที่ ~5887
- **การแก้**: ตัดการผูก undo/redo/delete/Esc ออกจาก listener ใหม่ เหลือเฉพาะ Space-pan และ F3/F7/F8/F9 · ย้ายการเคลียร์ draft (`wallDraft/pipeDraft/dragging`) ไปรวมใน Esc ของ listener หลัก
- **สถานะ**: ✅ แก้แล้ว

### DEF-02 — Undo/Redo ไม่ถูกบันทึก (Severity: **High**)
- **อาการ**: กด Undo แล้วหน้าจอ/ยอดเงินเปลี่ยนถูกต้อง แต่กด F5 กลับได้สถานะก่อน undo (ข้อมูลไม่ถูกบันทึก)
- **สาเหตุ**: `undo()` / `redo()` เรียก `applyData()` แต่ไม่เรียก `scheduleSave()` (ต่างจาก `commit()`)
- **การแก้**: เพิ่ม `scheduleSave()` หลัง `HIST.lock = false` ทั้งสองฟังก์ชัน
- **สถานะ**: ✅ แก้แล้ว (ยืนยัน: 19 → เพิ่ม 20 → undo 19 → reload ยังเป็น 19)

### DEF-03 — Redo stack หายเมื่อ reload (Severity: Low) — ✅ แก้แล้วใน v6.1
- **อาการเดิม**: ประวัติ undo/redo อยู่ในหน่วยความจำของหน้าเว็บ → หลัง F5 redo ต่อไม่ได้
- **การแก้**: เก็บ `HIST` ลง localStorage (`tsr.studio.hist.v1`) แบบ debounce 600 ms · เก็บสูงสุด **25 ขั้น** (`HIST_KEEP`) พร้อม fallback เหลือ 8 ขั้นถ้าโควต้าเต็ม · ตอน boot จะกู้ประวัติและยึด "ยอดบน = สถานะที่โหลดจริง" · `resetAll` ล้างประวัติทิ้ง
- **ยืนยัน**: เพิ่ม 3 รายการ → undo 2 (11 รายการ) → **reload** → `Ctrl+Y` ×2 → กลับเป็น 13 รายการ ✅ · ทดสอบ 30 ขั้น → เก็บ 25 ขั้น → reload → undo 3 ขั้น = 37 รายการ ✅

### DEF-04 — Undo/Redo เคลียร์ selection (Severity: Low) — ✅ แก้แล้วใน v6.1
- **อาการเดิม**: `applyData()` สร้าง id ใหม่ทั้งหมด → วัตถุที่เลือกหลุด และแผงขวากลับเป็นสถานะว่าง
- **การแก้**: เพิ่ม `selectionRef()` / `restoreSelection()` จำตำแหน่ง (index + ชนิด) ของสิ่งที่เลือกไว้ก่อน undo/redo แล้วคืน id ใหม่ให้อัตโนมัติ
- **ยืนยัน**: เลือก LG GIAN 13 → หมุน 90° → `Ctrl+Z` → ยังเลือกชิ้นเดิม ขนาดกลับเป็น 70×75 และ status ขึ้น “คงรายการที่เลือกไว้” ✅

### DEF-05 — ซูม/แพนไม่คงอยู่หลัง reload (Severity: Low) — ✅ แก้แล้วใน v6.1
- **อาการเดิม**: `applyData()` บังคับ zoom ให้อยู่ในชุด 20–120% และไม่เก็บ `panX/panY`
- **การแก้**: `serialize()` เก็บ `zoom/panX/panY` · `applyData()` รับ zoom อิสระ 20–400% และ pan ±20,000 · ล้อเมาส์/ปุ่มซูม/แพน/`ZOOM`/`Fit` เรียก `scheduleSave()` · ปุ่ม `+/−` เลื่อนเป็นขั้นมาตรฐาน 20→400 ได้
- **ยืนยัน**: ซูม 160% + แพน (70,45) → **reload** → ยังเป็น 160% และตำแหน่งเดิม ✅

## 5. ข้อจำกัดที่ทราบ (Known limitations)

1. 3D และ Excel ต้องต่ออินเทอร์เน็ต (CDN: Three.js, SheetJS)
2. ข้อมูลผูกกับเบราว์เซอร์เครื่องนั้น (localStorage) — ควรใช้ *ส่งออกไฟล์ผัง* สำรอง
3. Dimension เป็นแบบอัตโนมัติ (ขนาดพื้นที่) ยังไม่มีคำสั่งวัดระยะอิสระ
4. คัดเลือกหลายวัตถุพร้อมกัน (window select) ยังไม่มี
5. Layer manager เต็มรูปแบบ (สี/lineweight/lock) ยังไม่มี
6. Undo/Redo เก็บได้สูงสุด 40 ขั้นในหน่วยความจำ และคงอยู่ 25 ขั้นล่าสุดหลัง reload (ขั้นที่เกินจะถูกตัดทิ้ง)
