สร้าง Web Application แบบ Single Page ชื่อ “Prospect Management & Customer Intelligence Dashboard” โดยส่งโค้ดครบในไฟล์เดียวชื่อ `index.html` ใช้ HTML, CSS และ JavaScript แบบ Vanilla เท่านั้น ไม่ต้องใช้ Backend หรือ Database และต้องสามารถเปิดใช้งานได้ทันทีบน Browser

## เป้าหมายของระบบ
ระบบนี้ช่วยให้ Head of Sales และทีมงานสามารถ:
- เห็นสถานะยอดขาย Pipeline และ Forecast แบบ Real-time
- ระบุ Deal ที่มีความเสี่ยงยอดหลุด พร้อม Action ที่ต้องทำและผู้รับผิดชอบ
- ติดตาม Project ตั้งแต่เริ่มจนจบ โดยเห็น Stage, Owner, Deadline และ Blocker
- ติดตาม Customer Journey หลังการขาย ตั้งแต่ติดตั้งจนถึงการซื้อซ้ำ
- วิเคราะห์ Customer Intelligence เพื่อหาโอกาสขายซ้ำและความเสี่ยงในการสูญเสียลูกค้า

## Design Requirement
- ออกแบบ Modern SaaS Dashboard ที่ดู Professional ใช้งานง่าย
- ใช้ภาษาไทยเป็นหลัก และมีคำอังกฤษสำหรับคำธุรกิจ/ระบบได้
- ใช้ Google Font: Prompt หรือ Sarabun
- ใช้ Font Awesome CDN สำหรับ Icons
- ใช้ Chart.js CDN สำหรับกราฟ
- รองรับ Responsive ทั้ง Desktop, Tablet และ Mobile
- ใช้สีหลัก:
  - Navy: #0F2B46
  - Blue: #2563EB
  - Green: #16A34A
  - Orange: #F59E0B
  - Red: #DC2626
  - Background Gray: #F8FAFC
- มี Sidebar ทางซ้าย และ Main Content ทางขวา
- มี Hover Effect, Transition, Card Shadow, Progress Bar และ Modal ที่ดูทันสมัย
- ห้ามใช้ Framework เช่น React, Vue, Angular, Bootstrap
- ใช้ Mock Data ใน JavaScript
- โค้ดต้องมี Comment แบ่งส่วน HTML, CSS และ JavaScript ชัดเจน

## Sidebar Menu
สร้าง Sidebar ที่กดสลับหน้าได้โดยไม่ Reload หน้าเว็บ:
1. Dashboard
2. Sale Monitor
3. Project Tracking
4. After-Sale Service
5. Customer Intelligence
6. Reports
7. Settings

เมื่อกดเมนู ให้เปลี่ยนเนื้อหา Main Content และแสดงเมนูที่กำลังใช้งานด้วย Active State

# หน้า 1: Dashboard

## Header
- ข้อความต้อนรับ: “สวัสดี, Head of Sales”
- แสดงวันที่ปัจจุบัน
- ปุ่ม Notification พร้อม Badge จำนวนแจ้งเตือน
- Profile Avatar

## KPI Cards
แสดง Card จำนวน 4 กล่อง:
1. Sales Pipeline: ฿12,450,000
2. Forecast เดือนนี้: ฿4,850,000
3. Deals at Risk: 8 Deals
4. Overdue Actions: 14 Tasks

แต่ละ Card มี Icon, สีแยกตามประเภท และตัวเลขเปรียบเทียบกับเดือนก่อน เช่น +12.5%

## Dashboard Content
- กราฟ Pipeline แยกตาม Stage: Prospect, Qualified, Proposal, Negotiation, Won, Lost
- กราฟ Sales Forecast รายเดือน
- ตาราง “Deals ที่ต้องติดตามด่วน” เรียงตาม Risk Score สูงสุด
- กล่อง “Today’s Priority Actions” พร้อม Owner และ Due Date
- กล่อง Alert เช่น:
  - “3 Deals ไม่มีการติดต่อเกิน 7 วัน”
  - “2 Deals มีโอกาสปิดในเดือนนี้ แต่ยังไม่มี Proposal”
  - “4 Service Tickets ใกล้เกิน SLA”

# หน้า 2: Sale Monitor

หน้าหลักของระบบ ใช้แนวคิด Quick Win / Priority 1

## หัวข้อหน้า
Sale Monitor: Pipeline, Risk & Forecast

## องค์ประกอบ
- Filter ตาม Sales Owner, Sales Team, ช่วงเวลา, Stage และ Risk Level
- Search Box สำหรับค้นหาชื่อลูกค้า หรือชื่อ Deal
- ปุ่ม `+ Add Deal`
- ปุ่ม `Export Report`
- ปุ่ม `Refresh Data`

## Deal Pipeline Table
สร้างข้อมูลตัวอย่างอย่างน้อย 10 Deal พร้อมคอลัมน์ดังนี้:

| Deal Name | Customer | Owner | Value | Stage | Probability | Expected Close | Last Activity | Risk Score | Next Action | Status |

ให้แสดง Badge สีตาม Status:
- Healthy: สีเขียว
- Need Attention: สีส้ม
- At Risk: สีแดง
- On Hold: สีเทา

## Risk Score Logic
สร้างฟังก์ชันคำนวณ Risk Score 0–100 โดยพิจารณาจาก:
- ไม่มี Activity เกิน 7 วัน: เพิ่ม Risk
- Expected Close ใกล้ถึง แต่ยังอยู่ Stage Prospect หรือ Qualified: เพิ่ม Risk
- Probability ต่ำกว่า 40%: เพิ่ม Risk
- ไม่มี Next Action: เพิ่ม Risk
- Status เป็น On Hold: เพิ่ม Risk

ให้เรียงตารางตาม Risk Score ได้ และมีปุ่ม Sort

## Deal Detail Modal
เมื่อคลิกที่แถว Deal ให้เปิด Modal แสดง:
- ชื่อ Deal และชื่อลูกค้า
- มูลค่า Deal
- Stage ปัจจุบัน
- Probability
- Expected Close
- Sales Owner
- Activity Timeline
- เหตุผลที่ระบบประเมินความเสี่ยง
- AI Suggested Action
- ปุ่ม `Update Deal`
- ปุ่ม `Add Activity`
- ปุ่ม `Mark as Follow-up`

ตัวอย่าง AI Suggested Action:
“ควรนัดประชุมกับผู้มีอำนาจตัดสินใจภายใน 3 วัน เนื่องจากดีลใกล้วันปิดการขาย แต่ยังไม่มีการยืนยันงบประมาณ”

# หน้า 3: Project Tracking

Use Case: Strategic / Big Bet

## หัวข้อหน้า
Project Tracking: End-to-End Project Visibility

## KPI
- Total Projects
- On Track
- At Risk
- Delayed Projects

## Kanban Board
สร้าง Kanban Board แบบ Drag and Drop จำนวน 5 คอลัมน์:
1. Planning
2. Sales Handover
3. Installation
4. Testing & Acceptance
5. Completed

แต่ละ Project Card แสดง:
- ชื่อ Project
- ชื่อลูกค้า
- Project Owner
- Progress %
- Deadline
- Risk Status
- Blocker
- Progress Bar

ใช้ข้อมูลตัวอย่าง:
- บริษัท ABC จำกัด — ระบบ CCTV — Progress 75% — At Risk — รออุปกรณ์
- บริษัท XYZ จำกัด — ระบบ Network — Progress 40% — Need Attention — รออนุมัติแบบ
- บริษัท DEF จำกัด — ระบบ Access Control — Progress 90% — On Track — ไม่มี

## Project Detail Modal
เมื่อกด Project Card ให้เปิด Modal พร้อม:
- ชื่อ Project และลูกค้า
- Project Timeline
- รายการ Task
- Owner ของแต่ละ Task
- Deadline
- สถานะ Task
- Blocker
- ผู้เกี่ยวข้องจาก Sales, Marketing, Service และ Installation
- ปุ่ม `+ Add Task`
- ปุ่ม Update Status

เมื่อย้าย Card ด้วย Drag and Drop ให้แสดง Toast Notification:
“ย้ายสถานะ Project สำเร็จ”

# หน้า 4: After-Sale Service

Use Case: Customer Journey หลังการขาย และการรักษาลูกค้า

## หัวข้อหน้า
After-Sale Service Tracking System

## Customer Journey
แสดง Journey แบบ Timeline:
Installation → Active Use → Service → Maintenance → Complaint → Follow-up → Repeat Purchase

## KPI
- Customer Health Score เฉลี่ย
- Open Tickets
- Tickets Over SLA
- Repeat Purchase Opportunities
- Open Complaints

## Service Ticket Table
สร้างข้อมูลตัวอย่างอย่างน้อย 8 Tickets พร้อมคอลัมน์:

| Ticket No. | Customer | Product/Service | Issue Type | Priority | Assigned Technician | Open Date | SLA Due | Status | Next Action |

กำหนดสี Priority:
- Critical: สีแดง
- High: สีส้ม
- Medium: สีเหลือง
- Low: สีเขียว

## Customer Detail Modal
เมื่อกดชื่อลูกค้า ให้แสดง:
- ข้อมูลลูกค้า
- สินค้าและบริการที่กำลังใช้งาน
- ประวัติการติดตั้ง
- ประวัติ Service และ Maintenance
- Complaint History
- Ticket ที่ยังเปิดอยู่
- Customer Health Score
- Suggested Follow-up
- Repeat Purchase Opportunity
- ปุ่ม `Create Ticket`
- ปุ่ม `Schedule Maintenance`
- ปุ่ม `Contact Customer`

## LINE OA Service Update MVP
เพิ่ม Card สำหรับจำลองการแจ้งสถานะงานผ่าน LINE OA:
- เลือก Ticket
- แสดง Template ข้อความ:
  “เรียนคุณ [ชื่อลูกค้า] ขณะนี้ทีมช่างกำลังดำเนินการตรวจสอบ Ticket #[เลข Ticket] คาดว่าจะอัปเดตผลภายใน [เวลา]”
- ปุ่ม `Send LINE Update`
- แสดงสถานะ Sent หรือ Pending
- เมื่อส่งสำเร็จให้แสดง Toast: “ส่งข้อความอัปเดตให้ลูกค้าเรียบร้อยแล้ว”

# Interaction และ JavaScript

ต้องทำให้ใช้งานได้จริงด้วย JavaScript:
- สลับหน้า Sidebar ได้โดยไม่ Reload
- Filter ตาราง Deal ได้
- Search Deal และ Customer ได้
- Sort ตารางตาม Risk Score ได้
- กดแถว Deal เพื่อเปิด Deal Detail Modal ได้
- กด Project Card เพื่อเปิด Project Detail Modal ได้
- Drag and Drop Project Card ใน Kanban Board ได้
- ปุ่ม Add Deal เปิด Modal ฟอร์มเพิ่ม Deal จำลองได้
- ปุ่ม Add Task เปิด Modal ฟอร์มเพิ่ม Task จำลองได้
- ปุ่ม Refresh Data แสดง Loading State เป็นเวลา 1 วินาที
- มี Toast Notification ทุกครั้งที่ Update หรือ Send ข้อมูล
- Modal ปิดได้ทั้งปุ่ม X, ปุ่ม Cancel และคลิกพื้นที่นอก Modal
- ต้องมี Empty State สำหรับกรณีค้นหา Deal ไม่พบ
- ต้องมี Responsive Navigation สำหรับ Mobile

## สิ่งที่ต้องส่งมอบ
1. ส่งโค้ด `index.html` ที่สมบูรณ์เพียงไฟล์เดียว
2. รวม HTML, CSS และ JavaScript ไว้ในไฟล์เดียว
3. ใช้ CDN สำหรับ Google Font, Font Awesome และ Chart.js
4. ห้ามตัดโค้ด ห้ามใช้ Placeholder เช่น “ใส่โค้ดต่อเอง”
5. ต้องสามารถ Copy ไปบันทึกเป็น `index.html` และเปิดใน Browser ได้ทันที
6. เริ่มคำตอบด้วยโค้ดเต็มภายใน code block ชนิด html เท่านั้น
